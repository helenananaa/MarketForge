# 可预测订单流与报价反馈实验

本轮以此前 `persistent_index_anchor + book_slope_flow` 组合为控制；该组合没有通过整体市场统计验收，不是生产默认。保留300bot、4小时、主窗口[2h,4h)、1秒观察时钟，以及41、7、19、73固定种子。新增211作为未参与本轮候选选择的短留出，不复用已经看过结果的101充当新留出。

## 单一机制假设

持续同向主动成交是新数量，但其方向／速率可能已经能从公共流量记忆中预期。每次直接在当前公共中间价上增加完整数量的供给曲线影响，可能放大已包含在报价中的可预测压力。

新增显式开关 `flow_surprise`，使用做市商原有的公开流量指数记忆及半衰期，不新增数值系数：

```
decay = 0.5 ** (elapsed_ms / existing_flow_half_life_ms)
expected_signed_quantity = previous_flow_signed * (1 - decay)
quote_interval_surprise = newly_observed_signed_quantity - accumulated_expected_quantity
```

先预测，再观察本次公共成交。仅将上述意外流量输入既有的外部可见供给曲线；库存／指数逻辑、原始流量毒性／价差响应、撮合、手续费、资金、套利上限、目标仓位和拆单生命周期保持原样。预测只使用参与者已经观察到的公共信息；完整历史成交账本仅供事后分析，不提供给agent。

持续买流趋于不再反复额外抬价，但突然反向或超预期的数量仍有冲击，可能比原响应更强。没有新流量而预期买流缺席，也可以形成负向信息更新。这是需要实证检验的报价模型，不等于唯一正确的有效市场公式。

预测量按报价间隔累积，随状态恢复；重复时间戳不得重复预测。1.0.0拒绝新键；缺省关闭不改变冻结配置／快照。与其他开关一样，改变配置身份后不能把旧配置状态直接冒充新配置恢复。

## 复验与拒绝规则

工作区另有此前新增的内存／日志实现，予以保留并另行冻结。先用当前完整代码重放旧组合的种子41四小时，要求原始回执与此前Linux回执字节一致。再要求新增模型关闭时的候选程序与当前控制程序字节一致；不把底层变化混入机制效果。

在任何新候选结果产生前，冻结四种子及211的控制／候选全部配方。两组只差一个布尔键，所有数值输入保持一致。初筛后按联合指标决定推进：波动、1m／5m影线、收益及绝对收益自相关、同向序列、基差常态与尾部、真实未对冲时间、流动性和成交活跃度。若只是把波动重新压平，不能接受；失败分组不得删除或据新结果调数值系数。

继续使用四小时范围，不把它称为12小时资格。原始成交、BBO、实际资产和父需求账本分别核对；同波报价机会不等于跨市场原子成交保证。

内存优化路径使用逐笔输出及执行档案流式落盘，先用完整回执字节一致性检查守住交易语义。每次运行使用独立档案目录和完成摘要；保护停止、无有效完成回执或错误模拟时钟都不能计为完成。本任务只使用自己的临时资源单元及内存采样，不回收全局缓存、不改WSL全局设置、不关闭其他项目。

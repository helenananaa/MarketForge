# 背景市场与交易行为

增强配方新增基差套利、公共风控减仓、POV 和共同消息事件；网页默认启用 33 bot
联动市场。旧的 20／23 bot 配方保留，配置与边界见 [增强市场行为](MARKET_BEHAVIORS.md)。

基础现货配方使用同一份 Rust 导出的配置，创建并自动启动 20 个背景交易者。
人类账户 20、30 各有初始现金 10000 和 20 单位现货；背景账户 100–119 各自独立，现金和持仓有限。
已有房间保持原配置，使用新房间名称体验这批行为。旧五种 bot 的逻辑与存档格式没有改变。

## 参与者

| ID（版本均为 `1`，协议 `bot.v1`） | 行为 |
|---|---|
| `DynamicMarketMaker` | 多档 post-only 报价；根据偏离目标库存的程度移动报价中心；根据近期中间价绝对变化的 EWMA 扩大价差、缩小数量；波动达到阈值或保证金告警时撤单。价格/价差改变后先撤旧单，在后续观察确认后再报价。 |
| `ValueTrader` | 对照私人估值与盘口，在价差超过阈值时下有价格上限的 IOC；可设置估值变化的仿真时点、幅度和信息延迟。 |
| `TrendTrader` | 缓存有限观察窗口；价格变化超过阈值时朝目标仓位交易；信号消退时退出到基准库存，反向信号切换目标。现货不借币做空。 |
| `AdaptiveNoiseTrader` | 随机是否交易、数量、间隔和挂单价格；方向具有可调持续性；混合限价单与有价格限制的主动单；限制挂单数并撤销超时订单。 |
| `ExecutionTrader` | 带启动时点、目标数量、截止时间、单笔上限和价格保护的累积 TWAP；进度依据实际持仓变化，未成交或部分成交留下待执行数量；截止时停止。可出现未完成任务。 |

所有策略通过原有注册器、交易网关、账户风控、调度器与日志提交订单。
前端从 `GET /bots` 获取参数，不需要硬编码新策略表单。

公共参数包括 `decision_interval_ms`、`jitter_ms`、`order_ttl_ms`、`inventory_cap`、
`max_qty` 和 `fee_buffer_ppm`；具体有效参数、默认值和边界以 bot 描述为准。
`inventory_target` 是做市及趋势策略的基准库存。

仓位检查计入反向方向各自最坏情况下的现有挂单，不依靠买卖单相互抵消。
现货买单按可用现金和估计手续费限量，卖单按可用库存限量；合约新开仓采用完整名义金额做保守预检，不假设杠杆。
合约保证金告警时先撤挂单，再发 reduce-only IOC 减仓。交易所风控仍是最终裁决者。
`fee_buffer_ppm` 应至少覆盖所用市场的手续费；不匹配时交易所仍可拒单。

每个实例应独占一个房间/品种账户。策略按该账户的全部订单处理撤单，并按其净持仓计算拆单进度。
与人类或其他策略共用账户会失去订单归属和成交进度的准确性。
策略发出可能吃到自己反向挂单的订单时，先撤销这些挂单；没有观察到撤单成功之前不执行该笔交易。
这不是覆盖其他入口的交易所级 self-trade prevention。

## 配方与仿真时间

默认配方包含 3 个做市商、4 个价值交易者、3 个趋势交易者、8 个噪声交易者，以及买卖各 1 个拆单执行者。
不同实例使用不同参数、资金和派生随机种子。配方的派生种子限制在 JavaScript 可精确表达的整数范围内，Rust、Python 与前端读取一致。
所有随机状态、历史窗口、订单年龄、计划时点与执行进度都保存在版本化 bot state 中。

在 60000 ms 仿真时间，价值交易者的私人估值上移 12 ticks，信息延迟分别为 0、4000、8000、12000 ms。
这是可重复的合成信息场景，改变参与者的估值，不改写成交价。价格变化必须由交易和盘口变化产生。
原配方是有限现货市场，不自动加入合约。网页默认使用基于它扩展的[现货／永续绑定配方](SPOT_PERP_LINK.md)，新增 3 个永续做市商；取消“绑定永续”可继续使用原配方。

决策、订单年龄和事件时点依据 `market_time_ms`。趋势窗口按每次观察取样，EWMA 用 ticks 度量，并非年化波动率。
房间默认每 500 ms 墙钟推进一个 1000 ms 仿真步；机器人在每个观察机会自行判断是否到达各自决策时点。
手动仿真每步仍推进 1000 ms；在这里并不宣称墙钟与仿真时间等速，也不模拟亚步级网络延迟。
订单 TTL 从策略第一次观察到订单开始计算，因暂停或忙碌而延迟观察时不会自动在撮合器内到期。
截止时间是决策时的检查，异步返回的动作仍按现有网关规则提交；没有新增订单级 `valid_until`。

## 使用

创建新市场（复用已有 exchange-server）：

```powershell
.venv/Scripts/python.exe scripts/background_market.py --room background-demo --seed 7
```

Bearer 模式可通过 `MARKETFORGE_AGENT_ADMIN_TOKEN` 提供运营身份。
`--dry-run` 仅打印完整请求，不创建房间。
脚本不会覆盖已有房间，也不会替已有账户充值。

离线运行 300 步、种子 7 的确定性实验，输出成交数量、撤单数量、拒单回执、每个 bot 的成交量及最终状态：

```powershell
cargo run -p exchange-core --example background_market -- 300 7
```

重新生成前端和 Python 共用的配方：

```powershell
cargo run -p exchange-core --example background_market -- --export scripts/fixtures/background_market.json
```

## 证据边界

单元和集成验证覆盖资金/库存约束、信息延迟、波动退场、趋势退出、部分成交与截止、挂单年龄、自成交规避、随机状态恢复，
以及完整市场在决策保存、动作提交前后中断时的恢复一致性。Python 验收启动独立本地 HTTP 服务，检查注册表、自动运行、实际成交和 bot state。

这一批完成的是可解释、可回放的合成订单流。尚未根据实盘订单簿校准到达率、撤单率、订单大小、冲击响应或收益统计；
基础现货配方不含消息和套利；增强配方已提供合成公共消息与现货／永续套利，联动市场已有资金费率。
外部公共新闻订阅、信息权限和独立行情／订单网络延迟仍未实现。
LLM 交易员可加入这个现货房间，用自己的独立账户参与；其模型、容器和外部研究能力仍使用现有 `agent.v1` 服务。

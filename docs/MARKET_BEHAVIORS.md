# 增强市场行为

网页“创建仿真市场”默认开启“绑定永续”和“增强行为”，创建 33 个有限资金的背景
bot。关闭增强行为使用原来的 23 bot 联动市场；关闭绑定永续使用原来的 20 bot
现货市场。只影响新房间，不覆盖或充值旧账户。

```powershell
$env:PYTHONPATH = "$PWD\python"
.venv/Scripts/python.exe scripts/behavior_market.py --room behavior-market --seed 7
```

`--dry-run` 打印请求，`--export` 导出 JSON。网页和 Rust 撮合测试读取
`scripts/fixtures/behavior_market.json`，Python 测试检查它与配方生成函数一致。
内置目录有 15 个策略；Pine 插件需要另行安装。
勾选“盘口反馈与杠杆”可创建 38 bot 配方，具体行为与边界见
[盘口反馈与永续动机](MARKET_MICROSTRUCTURE.md)。默认仍使用 33 bot。

## 基差套利

`BasisArbitrageTrader` 配置 `leg: "Spot"` 或 `"Perp"`，以及对方的
`hedge_instrument_id`。配方给两条腿同一个专用账户 400、不同交易品种；每个
“账户、品种”组合由一条腿独占。初始现货和合约仓位都为零，不能与人工交易、
其他策略或资金划转混用。只支持同一交易所、明确绑定的现货／永续对和净持仓模式。

现货腿比较 **永续买一 − 现货卖一 − 两条腿的往返费用预算**，达到
`entry_basis_ticks` 才买现货。永续腿按实际买到的数量开空，部分成交只对冲实际
数量；尚未对冲时现货腿不再买入。两条腿都受资金、库存、价格和时效约束，没有
原子成交假设。增强配方另有两个永续噪声交易者提供主动订单流，做市商依据库存压力
调整报价，使两个市场的成交价可以形成可交易的基差。

`hedge_timeout_ms` 记录持续未对冲的时间；超时、合约价格来源失效或保证金不健康
时进入退出状态。正常价差收敛到 `exit_basis_ticks` 也退出，该阈值必须小于入场
阈值。退出先卖现货，永续腿观察剩余数量后用 reduce-only 买单平空。没有深度时
可以保留未完成仓位，直到实际成交，不伪造平仓。

第一版只做买现货／卖永续的正基差交易，不借币、不做空现货、不自动优化资金费
收益。预算使用全额名义金额，较保守；实际费用仍由交易所结算。未对冲计时、
退出状态、循环次数和冷却时间都可恢复。

## 公共风控退出

五类原生背景策略、POV 和消息策略可配置 `risk`：

```json
{
  "max_drawdown_ppm": 150000,
  "trailing_stop_ppm": 180000,
  "max_volatility_ticks": 25,
  "min_margin_buffer_ppm": 0,
  "cooldown_ms": 15000
}
```

各阈值为零表示关闭，旧配置默认关闭。权益回撤以观察到的权益高点为基准；追踪
止损以本次同方向持仓的有利价格高点／低点为基准。保证金缓冲使用
`(equity − max(自身维持保证金, 组合维持保证金)) / equity`。

触发后先撤自己的挂单，后续观察确认结果后逐步减仓。退出锁定到实际空仓，随后
进入冷却期；价格反弹不会中途重新开仓。合约退出使用 reduce-only，现货退出受
可卖库存限制。无深度时仍处于退出状态。`risk.trigger`、`exits`、`exiting` 和
`cooldown_until_ms` 可解释行为。

原生合约策略要求净持仓模式，遇到 Hedge 模式会拒绝运行，避免忽略双腿的总敞口。
本覆盖层尚未包裹 legacy 五类策略、Pine 或 LLM 插件。基差策略使用自己的成对
风险退出。增强配方未给目标执行者开启风控；自定义开启时，净仓位进度可能下降，
执行任务也可能因此未完成。

## POV 成交量执行

`PovExecutionTrader` 保留目标数量、开始时间、最大子单、价格保护和硬截止时间，
增加 `participation_ppm` 与可选 `deadline_urgency_ms`。

宿主从完整成交回执计算累计成交量，排除该账户作为 maker 或 taker 的全部交易。
首个有效决策记录基线，不追补启动以前的市场成交量。正常累计额度为
`floor(基线以后外部成交量 × participation_ppm / 1000000)`，实际成交不足留下
后续执行额度；默认不会因没有成交量而凭空下单。

`deadline_urgency_ms > 0` 明确允许最后一段时间放宽参与率以追赶目标，但不放宽
价格和资金约束。决策达到截止时间停止下单，子单也带提交截止时间。余额、库存、
深度不足或旧决策过期可以导致未完成，进度只来自实际净仓位。缺少或截断历史时
停止新子单。本版是 POV，没有实现预测成交量曲线的 VWAP。

行情历史仍有 4096 个非空 bar 和 4096 个自身成交的上限。累计外部成交量使用
十进制字符串传输，避免浏览器整数精度损失。

## 共同消息

`scenario.market_events` 是创建时冻结、写入房间快照和创建日志的公共仿真时间表。
最多 256 条，ID 唯一、按发布时间排序，必须指向存在的品种。

```json
{
  "id": "news-up", "instrument_id": "V-BTC-SPOT",
  "published_at_ms": 45000, "expires_at_ms": 110000,
  "impact_ticks": 18, "headline": "仿真事件：需求预期上调"
}
```

观察只暴露已经发布、对应本品种的事件。`MarketEventTrader` 用
`information_delay_ms` 和 `confidence_ppm` 延迟、缩放价值影响，用
`crowd_strength_ppm` 跟随自己的价格窗口；不同实例对同一消息可产生不同订单。
过期消息不再影响估值，接收 ID 仍可审计；风控或交易冷却期也继续更新消息。

消息只改变交易者判断，价格、成交量和盈亏由撮合记账产生。第一版是可重放的
合成消息，没有外部新闻接入，也没有运行中增删时间表的接口。

## 时效与恢复

跨标的观察来自同一房间锁，只含对方公开盘口和本账户状态。两腿各自走原有
gateway、调度和持久化流程，不重新提交已完成动作。

新策略的保护子单使用 `order_ttl_ms` 作为决策有效期，默认 6000 仿真毫秒；
POV 还受任务截止时间限制。有效期与决策周期分别控制，慢决策仍可能被拒绝。
actor 层拒绝保留原始命令用于持久化，过期拒绝不会使整个自动交易 worker 停止。

验证包括实际双腿成交和退出、对冲深度消失后的部分成交、消息发布边界、排除
自身成交的成交量、风控退出与冷却、保存决策与部分提交后的恢复，以及完整混合
市场和隔离 HTTP 自动运行。具体证据见
[首轮验证记录](validation/2026-10-08-market-behaviors.md)和
[吞吐与数据库恢复补充记录](validation/2026-10-08-market-behaviors-followup.md)。
补充验证覆盖 1000 步吞吐与内存门槛、实际 PostgreSQL 与服务重启及未完成 POV
的恢复。它们仍是有限规模的合成市场验证，不证明持续多小时运行或真实网络延迟。

现货＋永续的公共历史成交参考、拟合配方和留出样本对比见
[历史样本校准](MARKET_REFERENCE_CALIBRATION.md)。配方保留原有结构；已有实测
价格尺度、成交量、买卖方向延续性和基差统计，成交密度与波动等仍存在明显差距。

# 有限母订单与可见流动性执行实验

本阶段只改变现有 ExecutionTrader 的子单执行机制。冻结上一轮 raw-flow 控制配方（指数锚／供给曲线实验控制，非生产认证）；不启用被拒绝的 flow_surprise。原始业务方向、目标总量、配置开始时刻、期限、max_qty、滑点上界、账户资金、费用、做市／套利策略不变。

原执行者已有有限母订单及 TWAP 累计应完成量，不能声称本阶段新发明了持续需求。候选保留这些需求，改为只吃当前可见最优价外部数量、一次仅保留一个在途子单；成功提交不是成交。依据匹配账户、方向和真实子单订单号的权威执行反馈扣减需求，未成交债务保留到原期限。确认后允许在新的市场观察中重试，仍不超过原 TWAP 累计额度、max_qty、最优价数量和原保守资金检查。同一市场时刻不能重复决策。到期不依赖账户可用性或是否有盘口，迟到的真实成交确认可以校正已过期量，不重开期限。

原期限策略从实际首次激活计时，配置不变；逐账户报告实际激活与截止时刻，不冒称动态执行路径中的绝对截止时刻必然相同。需求账本恒等式为原始需求＝真实成交＋过期残余＋仍待执行。原策略独占账户的净仓位进度还将与实际成交核对，强平与风险退出单独识别。

新增 ExecutionTrader 1.1.0 显式 liquidity_aware 开关，默认不启用；1版拒绝该键，包括false。老快照不新增空字段，关闭路径必须重现旧种子41完整4h原始回执及执行档案哈希，然后才能复用此前四个固定种子41、7、19、73的真实控制。四种子及可选新种子271的全部配方在任何新市场结果出现前冻结。缓存副本不计新运行或新小时。

固定300bots、1秒时钟、每次4小时，主窗口[2h,4h)。先做新程序关闭路径复跑与种子41候选，再执行其余三个冻结候选；不据中途图形调数值。联合检查1m/5m/15m形态、价格和绝对收益自相关、厚尾、母订单完成／过期／耗时、订单方向和成交间隔、价差深度、单位订单跨档及冲击恢复、跨市场基差与实际套利残差。订单流持续不应被误当作价格必须机械持续的理由。若只是减少成交、积累更多过期需求或压低波动使图变好，不能采纳。失败结果完整保留。

四种子联合结果有足够收益才执行已冻结271独立短留出；拒绝机制不需要再用留出挽救。4h只作筛选，12h长周期、真实订单簿校准和跨日期泛化仍为独立缺口。后续做市补单／撤退策略、信息分歧等另做隔离实验，本阶段不混入。

资源策略在结果前制定：最多一个原生任务，原生退出后才做离线统计，避免上一轮分析进程与模拟竞争提交额度。依据此前9个完整4h任务原生峰值均不足0.8GiB，新批次主机提交启动门槛6GiB、客体可用8GiB；本任务单元MemoryHigh2G/Max4G/SwapMax2G，3GiB运行保护保持。资源门槛变化仅用于新的执行计划，不修改旧计划、经济输入、随机种子或模拟时钟。不回收全局缓存，不改WSL设置，不停止其他项目。

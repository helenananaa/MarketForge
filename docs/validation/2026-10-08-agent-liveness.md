# 外部交易员存活、状态与回放验证（2026-10-08）

本次补齐连接器心跳和原生会话恢复、决策有效期、运行状态面板，以及有限真实模型联调和录制回放。模型循环、历史、上下文管理继续由外部框架负责。

## 实现与受控回归

- 决策凭证默认 120 现实秒，可配置为 10–600 秒；过期或失联拒绝旧决策的新动作，已完成回执和未知订单按原身份核对不受影响。
- 会话约每 3 秒探测和报告心跳，15 秒到期。新传输有独立代际；旧传输不能通过 `decision_begin` 获取新凭证。连接器在原会话有限重试，明确区分框架、业务和策略的状态。
- 状态面板显示在线/活动/等待/重连、凭证、待核对订单、最近警报和工具、策略异常，区分现实观测时间与模拟市场时间。桌面及 390px 视口完成真实浏览器渲染检查；该界面检查使用 HTTP 测试数据，没有操作既有市场。
- 回归覆盖凭证超时、失联立即拒绝、旧心跳与旧传输拒绝、订单结果核对、有限重试、同会话续接、交付游标竞态、警报分页后的状态，以及真实交易所的两次回放一致性。
- 前端生产构建、Python 编译、`git diff --check` 通过。完整 Python 回归 82 项：79 项通过、3 项环境门控跳过；结果见忽略目录 `.local/validation/agent-liveness-python.log`。

## 真实模型与真实虚拟交易所

`scripts/validate_agent_framework_live.py` 使用本机 Codex CLI 0.144.5、该 CLI 公布的可用模型 `gpt-5.6-sol`、会话内低推理强度，以及单独启动的 Rust 交易所进程、临时工具服务和出资账户。没有使用现有用户房间，也没有修改全局模型或审批配置。

最终通过记录：`.local/validation/agent-framework-live-final/report.json`。

1. 模型读取市场、建立决策并自行选择警报条件。
2. 测试控制器将有限挂单的卖一价从 101 改为 105，并推进模拟时钟 3 步；警报在活动轮次中通过 `turn/steer` 交付同一会话。
3. 模型读取新行情、重新建立决策，以 105 ticks 买入 1 单位，然后进入等待。最终仓位 1、现金 99895，无第二次成交。
4. 关闭并重新启动框架进程，通过原 session ID 恢复原历史，MCP 仍读到同一仓位；恢复检查没有另开模型推理轮次。
5. 录下的 13 个有序业务步骤在两个新的真实交易所进程中不调用模型地重放，业务结果及最终观测摘要完全一致。独立回放 CLI 再次得到相同摘要：`1f34da47d3b94bf1ef028a7da747190c8fdaa18eb04d1c2baa67a591a44f43a3`。

该次测量：行情改变到警报约 218ms，警报到会话接受约 125ms，警报到交易被接受约 6750ms。这是单次本机受控样本，不是延迟保证。门控暂缓第一次警报设置工具的返回，使活动轮次交付边界可重复；没有读取或保存模型隐藏思考内容。

真实推理消耗了提供商额度。框架报告的最终通过轮次累计输入 251249 tokens（其中缓存输入 227584）、输出 952。费用没有根据缓存或计费规则推算；其他失败尝试另有用量，不能把这份通过记录当作整次工作的总费用。

## 失败记录与验证边界

首次本机配置中的模型名不被该 CLI 支持，推理被拒绝。改用 CLI 公布的模型后，联调发现 MCP 写操作需要独立的工具审批设置；无人值守连接器之前将请求拒绝，尚未进入业务执行。修正了该会话内 MarketForge 工具的审批配置，其他服务器和人工表单不自动批准。失败记录保存在 `.local/validation/agent-framework-live*`，最终通过记录与失败记录分开保存。

真实模型活动中断和历史恢复在 Codex 上通过。OpenCode 的实际 MCP 连接、session 恢复通过；其活动中断仍由协议测试覆盖，没有做真实模型端到端联调。Docker 隔离验收、真实依赖安装和旧多交易员实时提供商流程的三个环境门控测试跳过。

本次证明受控目标下的工具、中断、重新决策、成交及恢复链路。自由目标下的长期自主交易质量、多日稳定性、跨主机迁移、故障频率和成本上限尚未得到认证。挂单及已发生交易不会因失联自动撤回；后台策略部署仍遵循已有设置。

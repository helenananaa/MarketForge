## 改动与保留的约束

- `RoomManager.executions` 使用现有分块共享 `History<ActorExecution>`。候选事务共享已封存的历史块，追加时只复制当前尾块；旧执行记录完整保留。新增长度及后缀迭代接口，提交、观察和训练路径不再为读取历史长度/尾部而展开全量数组。原切片导出接口与数组序列化仍兼容。
- 实时提交以当前锁内调度器为只读前驱，准备元数据与本批 bot 的稀疏更新。更新前验证版本、前驱 revision、成员数量和索引；日志成功后移动变化状态到原 roster。正常后台提交只返回确认，不再构造全体 bot 状态响应。
- 手动确定性步进、显式响应和周期完整检查点仍可生成完整调度器。既有完整日志与增量日志格式不变，不需要迁移。
- 保留 64 个结果的批上限、一个 bot 最多一个在途任务、锁外策略计算、epoch/config/full-state 过期检查、动作顺序和 gateway 风控。批内覆盖表模拟旧的顺序更新，重复 participant id 的既有匹配行为保留。无订单动作的决策仍持久化 bot 状态，未跳过风险、时钟或 TTL 更新。

## 仍存在的边界

这两处确认的复制热点已移除，500 bot 明显提速，但还不能宣称完整容量达标：两轮短测都未达到 40 步/秒基准，1000 bot 实时组撤单 P95 292.4ms 仍超过 250ms 基准。目标和阈值未降低。

全局 AppState 锁、观察准备、每笔动作的现有风险/预留/清算检查与全员每 tick 调度仍存在。周期完整检查点和显式导出仍有全量成本，完整历史仍持续占内存。本轮没有重做事件驱动调度、逐房间锁或风险增量算法。没有多小时运行、大量 bot PostgreSQL 容量、LLM/Pine 策略、浏览器帧率或真实市场资格证明。

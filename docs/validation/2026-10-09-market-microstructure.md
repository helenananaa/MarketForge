# 盘口反馈、永续动机和联合校准验证

日期：2026-10-09。实现范围是盘口压力／单向 maker 成交反馈、资金费参与者、
不同杠杆偏好的趋势参与者与主动减仓，以及固定现货＋永续历史样本的有界联合搜索。
代码未提交、未推送。工作区含其他任务的改动；本轮没有重置或清理它们。

## 实现和实际行为

内置目录由 13 增至 15 个策略；新增 `FundingRateTrader`、`LeveragedTrendTrader`。
`DynamicMarketMaker` 增加排除自身挂单的深度压力、两侧不同数量、单向 maker
成交后的撤单／冷却／数量恢复和换单滞回。新增状态支持快照恢复，旧配置默认关闭
这些反馈。共用账户预算、网关滑点保护、保证金和回撤风控继续生效。

38 bot 配方复用原 33 个参与者，额外分配两个资金费账户、三个杠杆趋势账户；
目标杠杆分别覆盖 1／2／5，资金有限且没有运行中充值。网页“盘口反馈与杠杆”
开关读取同一 JSON 配方，默认未勾选。96 bot 历史尺度配方是单独的研究输出，
没有替换网页默认 33 或可选 38 bot 的参数。

真实撮合受控测试验证：

- 正、负 20,000 ppm 资金费两种场景，策略实际收取 400 现金单位，对手支付 -400；
  两账户现金合计 200,000 守恒，12 步后实际持仓归零。该大费率是验证清算和方向的
  受控输入，不代表样本真实费率或策略净收益资格。
- 决策保存后、第一条动作提交后分别中断，序列化恢复的全部执行历史、资金费、
  账户、调度状态与下一订单 ID 和持续运行完全一致，没有重复下单。
- 场所允许 10 倍杠杆、bot 目标 5 倍的受控场景，实际开仓 40；指数从 11,000
  降到 10,000 后，保证金状态仍健康，bot 主动减仓至 29，敞口不超过真实权益的
  5 倍。流动性账户的有限本金在场景初始化时明确设置为 1,000,000。
- 单元测试核对排除自身深度、压力方向和两侧数量、撤单确认、重复成交 ID 恢复、
  冷却后渐进数量、资金费窗口／费率反向／周期退出，以及决策间隔前主动减仓。

## 联合搜索和留出比较

原始数据沿用官方校验过的 BTCUSDT 2025-01-02 现货与 USD-M 永续成交、当月
资金费率归档。源统计取 UTC 前一小时，前 1800 秒拟合、后 1800 秒留出。源归档
SHA256 和历史统计见 [历史样本参考](../MARKET_REFERENCE_CALIBRATION.md)。

十个候选粗搜索订单流人数、活动比例、市价比例、报价宽度与做市深度。下单尺度取
拟合段数量中位数，数量单位细化为 0.0001 BTC；方向延续概率修正为
`max(0, 2 * P(同方向) - 1)`。所有初始现金和库存有限、可审计。没有真实盘口数据，
所以报价、库存、资本分布仍属于模型假设，未作为真实盘口测量值。

每候选先运行种子 7、120 仿真秒，前三名再运行种子 19、120 秒；用拟合分数
平均值选出候选 7，分数 3.275018。活动比例 0.8，市价比例 0.9，到达人数系数
1，报价波动系数 0.2，深度系数 16、四档，总共 96 bot。两边初始报价半宽为
14／15 tick。然后固定参数，用种子 7／19／41 各运行 240 仿真秒，并在全部选择
完成后计算留出残差。基线是当前 `fitted_recipe` 的 33 bot／0.001 BTC 尺度。

基线种子 19 永续标准差为零只对应少量相邻活跃秒上的不变价格，不能视为良好
低波动市场。新配方三个种子的两边活跃秒数均显著增加，现货数量尺度接近留出，
但现货／永续成交密度仍低于留出，永续波动偏高，方向延续性仍不匹配。

现货代理按同时间、价格、方向、吃单 ID 合并连续撮合成交；永续代理按同 100ms
桶、价格、方向合并连续成交。原始撮合笔数全部保存，例如种子 7 新配方实际产生
现货 5926、永续 6625 条撮合成交，封闭窗口 `[0, 240秒)` 内代理聚合数分别为
3233／3859；240 秒边界上的实际成交不计入该窗口。仿真时钟仍按秒
推进，不能据此声称已复制真实 100ms 到达过程或完全相同的历史聚合边界。

研究模式直接复用策略对象，每单仍通过实际网关、账户预算、撮合和清算。其与耐久
调度器在原 33 和新 38 bot 配方下各 72 步的完整执行历史、订单 ID、资金费、
账户和策略状态精确一致。研究模式没有每步数据库检查点；数据库证据来自独立
38 bot 服务重启。每次研究运行保留 300 秒墙钟超时，没有提高超时掩盖失败。

探索过程留在 `.local/joint-market-calibration*`：最初耐久研究运行因每步快照开销
中止；第一次连续运行使用原始撮合笔数，在发现统计粒度问题后中止。随后一次
启动与 Windows 链接输出发生竞争，运行了旧可执行文件，被缺少吃单 ID 的校验拒绝；
重新构建成功后完成正式搜索。失败日志和回执均保留，没有计入正式结果。
最终从已完成的八候选报告复用通过来源／二进制／配方／统计核对的回执，再增加
两个活动与市价比例候选；最终选中参数未变。

正式输出：`.local/joint-market-calibration-aggregated-final/`，包含配方、映射、
十候选报告、各次完整成交／账户／状态，以及拟合和留出残差。

## 检查和后续缺口

Rust workspace 459 个测试通过；额外研究运行器一致性测试 1 个通过。
Python 校准 12 个、HTTP／配方 4 个通过；Clippy 全 workspace／all-targets 严格检查、
Rust 格式和网页 TypeScript／生产构建通过。HTTP 验证包含新 38 bot、原 33 bot、
原 33 bot 高速完整时间线。网页新增开关未单独做浏览器视觉验收。

仍缺多个历史日期／状态、较长独立种子运行和预先制定的统计接受区间；成交、波动、
数量和方向性尚未同时达标。还需要真实盘口与订单事件用于价差、撤单、队列和延迟
检验，以及更真实的资本／库存分布。maker 毒性只观察最近 32 条公共成交，可能
漏计；资金费策略未做现货对冲；主动减仓遇到流动性不足会留下实际风险。
结论是机制和本地行为验证完成、参考拟合明显改善，尚未通过真实市场相似性资格。

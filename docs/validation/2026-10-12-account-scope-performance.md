# MarketForge 局部账户同步与资金校验优化

2026-10-12，基线为 `2b8d7b76dc65ce722fdb1a4b4910a2217b73f8ad`，候选为本任务的修改。范围为 MarketForge；原有策略库暂存内容保持不变。验证时尚未提交；未推送或部署。

## 改动与资金安全

现货执行前的 venue 同步，改为比较该市场上一次成功同步时的持久化钱包根和现货账户根。只同步发生变化的账户，包含其他市场成交、转账、外部预留资金与新账户产生的变化。每个市场分别保存同步基线，不依赖会被预留资金对账清除的 dirty 集合。稠密变化、未知状态或恢复后的首次同步保留全量路径。

清算后的资金检查，改为比较上一次成功校验的钱包根，检查实际变动账户的所有资产。此前依靠资金费或对冲持仓例外而获准欠资的账户每次仍会复查，即使钱包未变；持仓关闭后例外失效仍会拒绝欠资。负预留、欠资判断和整数溢出检查保持原规则。只有所有检查成功才更新基线；候选事务失败仍回滚。

新增基线均为派生内存数据，Serde 不写入它们。恢复与不透明的市场可变访问会使基线失效；原有快照／日志结构、日志确认后安装候选状态的顺序保持不变。少于 8 个 venue 账户时继续直接全量扫描，不维护增量基线：这个规模下一个变动账户无法进入原有四分之一人口的稀疏分支。

另外补齐了基线已有的风险诊断构建错误：`risk_benchmark_realtime.rs` 初始化 `ObservationRequest` 时遗漏 `event_filter`。修正只有一行，从 registry 取得该字段，使 `--all-features` 检查能够完成。

## 固定工作前后对照

基线 core 从上述提交独立导出；前后使用字节相同的 `benchmark_account_scope.rs` 和相同依赖版本，均为默认 feature 的 Release。编译和测试结束后串行运行 ABBA × 2，共 8 次。每个程序正反顺序扫描 1、100、1000、10000 账户；每例执行 400 条命令，前 20 对预热，后 180 对计时。挂单／撤单场景始终只有账户 1 活跃；成交场景使用账户 1 和 2，其余账户均闲置，每例确实成交 200 笔。

计时包含公开 actor 命令路径的内部同步、校验、候选复制与安装；建账户、断言、最终业务状态与完整回执的序列化／哈希排除在计时窗外。历史增长、命令与成交数在前后相同。全部 14 种案例在所有正反轮次和前后版本间的最终业务状态及 400 条执行回执哈希严格一致。

- `cargo test --workspace --all-features`：614 通过、0 失败、15 忽略；设置 `MARKETFORGE_REQUIRE_POSTGRES_TESTS=1`，使用本任务独立 PostgreSQL 集群及新测试库。覆盖持久日志、资金费、保证金、清算、幂等、异步投影、重启和训练崩溃恢复。
- 新增 4 项账户范围回归：与全量路径逐笔执行和业务状态等价；跨市场成交、转账、新账户及恢复；闲置账户和其他资产欠资拒绝、失败不更新基线；现金不变但持仓关闭后的欠资例外复查。另验证已知输入只访问局部账户，反序列化后的首次访问恢复全量检查，派生基线不出现在快照中。
- Clippy 全 workspace／所有目标／所有 feature，`-D warnings` 通过；格式及 `git diff --check` 通过。
- PostgreSQL 端口 55442，fsync、synchronous_commit、full_page_writes 全为 on；测试结束后本任务集群已停止。没有连接或修改用户数据库。

首次 PowerShell 包装器将 cargo 正常 stderr 当作终止错误；修正包装器后继续。首次完整测试另有 11 个插件失败，原因是系统 `python3` 指向 Windows Store 别名，退出码 9009；将 PATH 指向本项目 `.venv/Scripts` 后，两轮完整全 feature／真实 PostgreSQL 验证均通过。先前日志均保留，没有放宽业务断言。

## 复现与范围

使用同一版本的驱动分别构建基线和候选：`cargo build --release -p exchange-core --example benchmark_account_scope`。然后执行 `python scripts/benchmark_account_scope.py --before <基线exe> --after <候选exe> --baseline-commit <基线提交> --output <新的输出目录> --rounds 2`。输出目录须不存在；运行器严格检查案例覆盖、工作数量及最终状态／回执一致性。

本次结果属于固定内存核心命令路径。HTTP、机器人异步实载、长期 RSS 和生产容量尚未测量；这些加速倍数不应直接转换为整个服务吞吐。持久化根共享避免深拷贝，但各市场保留上次同步版本的内存代价没有在本轮单独计量。完整源码与二进制哈希、各场景统计和验证回执见同名 JSON。

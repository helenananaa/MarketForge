# 房间平台与按身份看盘验收

2026-10-09，本次改动位于 MarketForge；CandleScope 页面和分析服务继续使用本项目 `vendor/candlescope` 内的源码副本。

## 已实现

流程为身份验证 → 房间大厅 → 创建配置 / 选择已授权房间 → 确认角色与账户 → 加入 CandleScope 看盘。
成员、账户分配、Bot 参数和启停、市场运行控制放在独立房间管理页；看盘页保留原图表、周期、指标、绘图、盘口和订单流组件。

| 身份 | 可见数据 | 写入权限 |
| --- | --- | --- |
| 房主 / 管理员 | 全部账户、当前委托、Bot 状态与配置 | 房间管理；账户交易由原后端授权检查 |
| 交易员 | 服务端分配的账户与委托、公共行情 | 自己账户的下单与撤单 |
| 观众 | 全部账户、当前委托、Bot 的公开状态与参数 | 只读；凭据字段隐藏 |

后端提供 `/identity`、房间 `/session`、按角色筛选的 `/workbench` 和仅管理员可读的 `/members`。
加入不会自行授予角色。下单、控制市场与 Bot 管理仍通过原有写入口校验权限。
观众可通过 HTTP/WS 只读账户观测；公共观测 `account_id=0` 清除账户、私有委托和 Bot 私有数据。
前端重新校验房间权限，撤销权限时停止订阅、清除旧账户并返回大厅。个人指标/绘图持久化键加入服务端用户 ID。
创建时未自动运行的 Bot 配置仍保存到调度器日志，重启后可以继续配置并启动。

## 验证结果

- 后端 `cargo test -p exchange-server --lib --target-dir target/candlescope-portal`：176 项通过。
  覆盖 Bearer 角色隔离、跨账户拒绝、观众写入拒绝、成员撤销、公共/观众 WebSocket 与凭据隐藏。
- 前端 simulation 与共享页面测试：35 项通过；类型检查和生产构建通过。
  新增验证权限响应字段顺序变化不会清除有效会话、越界账户与伪造权限拒绝、401/403 清除私有观测。
- 真实 PostgreSQL 房间 `mf-portal-20261009`：从浏览器创建房间，配置交易员/观众与账户 20，启动并暂停 Bot。
  交易员只能选择账户 20；实际市价买入 1，服务端指令 30 接受，持仓从 20 更新为 21。
  观众能只读全部 23 个账户、20 个 Bot，并看到账户 20 的更新；前端没有下单和管理按钮。
- 直接绕过 UI 发起 8 个跨账户、观众写入和非成员访问请求，均返回 403。
  非创建者的 `admin` 成员通过接口与实际管理页验证。
- 移除在线观众后，订阅拒绝、页面回到大厅且不再渲染账户；其 `/workbench` 返回 403。
  测试后恢复观众成员，房间保持暂停且 Bot 停止。
- 服务重启后，账户更新、房间权限、暂停状态及 20 个 Bot 模板保留。
- 浏览器验证 1s / 1m / 自定义 3m 周期，原盘口、逐笔和成交分布正常显示；最终流程无页面 JavaScript 异常。
  390×844 窄屏页面无横向溢出，收起侧栏后图表宽约 305 px。

本地证据在 `output/candlescope-workbench/portal-{http-proof.json,browser-final.log,server-tests.log,frontend-tests.log,typecheck.log,frontend-build.log}`。
截图在 `output/playwright/candlescope-workbench/portal-*.png`，包括大厅、角色确认、管理页、交易回执、观众、撤权和窄屏。
这些运行产物位于 Git 忽略目录。

## 当前边界

完整市场/账户规则和 Bot 策略参数使用场景 JSON 编辑；已有房间的合约与初始资金通过新建房间变更。

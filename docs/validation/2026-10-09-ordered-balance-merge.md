# 顺序合并账户与场所余额

承接 [共享事务表优化](2026-10-09-shared-transaction-tables.md)，按速度优先继续减少同步阶段查找成本。前驱是上轮完整工作区 Release，不是未修复 HEAD；所有改动仍未提交或推送。

## 实施与约束

- 现货交易前同步按账户 ID 顺序读取 quote/base 场所余额。密集账户集合与两个资产余额迭代器合并，减少逐账户反复查根账户树；只在选中账户时计算 available，再按原先 quote、base、同步写入顺序执行检查。
- 永续跨市场同步在密集且严格有序的账户集合之间使用游标合并，同名账户缺失仍按原规则跳过。peer 市场顺序不变，未实现盈亏、预留/初始/维持保证金仍使用原 checked 算术；场所余额也按 ID 合并读取。
- 请求密度不足约四分之一时，保留原索引/二分查找，避免少数高 ID 账户扫描大量无关账户。目标或 peer 账户顺序不满足要求时也保留原查找。全部所需账户仍经过原同步和风险校验，没有跳过全组风险检查。
- 新资产余额迭代器返回借用原始余额；扫过未请求账户时不计算 available，因此不会因为无关账户的极值而新增溢出行为。缺失资产/缺失账户的 fallback、溢出错误、已执行前缀与失败回滚不变。

没有新缓存、格式/版本变更、依赖或生产配置开关。相比上轮，仅 `exchange-core/src/account.rs`、`actor.rs` 不同；其他核心与服务端源码摘要一致。测试专用参照冻结了本轮前驱的现货同步和永续二分查找算法。

## 1000 bot 实际服务负载

使用前驱和新版冻结 Release，各运行加速模式和实时模式一轮。每轮预热 3 秒、采样 20 秒，随机独立 loopback 端口；同模式 recipe SHA256 一致、seed 7、1000 活跃 bot、相同 2048 MiB 内存护栏。加速模式目标 40 step/s（25 ms），实时模式目标 1 step/s（1000 ms）。没有并发运行本任务的测试或编译。

| 模式 | 版本 | step/s | 读取 P95 ms | 下单 P95 ms | 撤单 P95 ms | 峰值 MiB | bot 更新落后 step 中位数/最大 |
|---|---|---:|---:|---:|---:|---:|---:|
| 加速 | 前驱 | 16.073 | 68.05 | 96.01 | 102.73 | 267.75 | 23 / 31 |
| 加速 | 新版 | 15.697 | 90.24 | 76.85 | 83.95 | 280.81 | 22 / 30 |
| 实时 | 前驱 | 0.961 | 125.95 | 97.40 | 120.72 | 196.09 | 1 / 1 |
| 实时 | 新版 | 0.958 | 54.55 | 53.75 | 92.39 | 201.91 | 1 / 1 |

四轮客户端错误和 bot 错误均为空，均观察到 1000 活跃 bot。落后值按采样时 room step 与 bot 最近更新 step 的差计算，不代表墙钟毫秒延迟。加速模式吞吐下降约 2.3%，读取 P95 变差，下单/撤单 P95 改善；实时模式接口延迟改善，但吞吐受时钟目标限制。单轮前后异步路径与宿主机负载会变化，不能将本次延迟改善认定为稳定全服务增益；也没有证明达到 40 step/s。

加速模式保证金阶段累计计时 4.331→3.714 秒，scheduler apply 17.077→16.203 秒，而 journal 2.138→2.572 秒。它们不能相加，也不是相同逐笔交易工作量的计时；这些数据只说明仍需研究调度、日志与其他串行阶段。相比前驱，采样峰值内存增加约 13.1/5.8 MiB，不能据此归因于新游标（本轮没有新持久缓存）。原始 report、samples、metrics、scheduler 与日志均在 `.local/bot-margin-merge/{before,after}-1000-{fast,realtime}/bots-1000/`；汇总为 `comparison.json`。

## 冻结二进制语义对照

前驱 SHA256 `bd9dda3eac5224568a2a0fd6d3908f30ab94314a5d42274a1d2fce7e4f58bcec`；新版 SHA256 `8fb0d2c159a41ea79c2814c25bfd5a7657b9bf902ff05fba64b9450d33994104`。两个生产二进制执行相同 335 个固定 API 操作，实际成交 80 次、风险拒绝 5 次，时钟前进至 280 step；逐操作响应和最终账户、盘口、消息、时钟、调度快照完全相同。

该对照配置 38 bot，自动 worker 关闭，交易由固定 API 操作触发；因此不作为原生策略自动运行一致性的证据。结果与完整回执在 `.local/bot-margin-merge/fixed-trading-comparison/`。

新版生产二进制另完成两项原生策略资格验证：

- PostgreSQL 独立临时数据库，38 bot、100 ms 间隔、压缩时间线：30 step 暂停，数据库和服务均重启，账户、盘口、消息、时钟与调度状态精确相同；恢复后至 60 step，两侧 POV 截止完成量为 12/19，无 bot 错误，全部 event bot 收到两条事件。该短测试不声称原始完整时间线或数据库吞吐达标。回执在 `postgres-boundary-recovery/`。
- 原始完整时间线，33 bot、25 ms 间隔、1000 step：24.984 秒完成，POV 买卖均完成 25/25，全部事件送达，无 bot 错误；观察延迟 0 模拟毫秒，进程峰值约 92.58 MiB，低于 512 MiB 护栏，未延长订单 TTL。回执在 `original-1000/`。

上述测试使用本轮新版 SHA256；都是本地合成模拟验证，未做真实市场校准。

## 剩余速度空间

保证金输入和请求仍会构造，所需风险检查仍执行；本轮减少查找，未引入可以跳过完整同步的版本证明。日志路径另检查到恢复 JSON 验证和 payload 构造，以及 PostgreSQL 插入路径的验证调用。消除重复验证需要保留所有入口的校验与错误优先级，并在对应持久化后端测量，本轮没有改动日志语义或声称数据库吞吐提高。

实际高 bot 服务仍受串行 writer、清算、策略调度和 checkpoint 影响，完整服务的稳定收益需结合上述负载结果判断。最终源码、冻结二进制、负载和资格验证摘要核对通过，见 `.local/bot-margin-merge/final-verification.json`；任务测试服务均已退出，独立 PostgreSQL 集群已停止。

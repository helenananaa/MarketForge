# Pine 日志状态移交与千 bot 历史负载对照（2026-10-12）

分段诊断确认提交到日志线程前的完整 mutation 克隆是可直接消除的热点。首轮 30 秒窗口该段累计 7976.8ms；完整 scheduler materialization 11 次累计 3762.7ms。日志队列累计等待 10924.5ms，但包含并发等待，不能当作处理时间或与其他段相加。

修改由已拥有 candidate 的调用者把 PendingJournalMutation 移交日志线程；存储接受后返回原状态，再安装到调度器。空订单结果的 delta/full checkpoint 均沿这条路径，控制幂等冲突只保留小的请求指纹。原有借用接口继续供其他调用者使用。失败不安装，调用取消后的外层 durable task 仍负责完成已接收提交。没有调整 checkpoint 频率、四 worker 数量、风险/订单语义或历史上限。

## 同历史、同配方的 A/B/B/A

实际 1000 个 Pine，另有 38 个原生流动性 bot；MA/RSI/breakout 三份已有增量资格源码，692 组不同输入，10/15/30 秒周期。通过真实网关预热 192/128/64 根非空收盘 K 线。四轮 recipe 和启动前完整 candle JSON 的 SHA256 分别完全相同。默认事件提前过滤关闭。每轮 20 秒暖机、30 秒测量，目标 1 仿真步/墙钟秒，阈值和订单 P95 250ms 要求保持不变。

两个诊断 release 先构建和验证，再串行运行四轮；编译和其他 benchmark server 采样均为零。冻结源码、二进制、输入、完整调度器结果和逐进程采样保存在 `E:\projects\MarketForge\.local\pine-state-profile-20261012`。使用一个任务专用 Cargo target 顺序重建；before 二进制在候选编译前另行保存，哈希不同，未用共享生产 target 的 Fresh 结果作对照。

## 正确性与边界

Rust workspace、诊断构建 clippy、普通构建 check 的日志和计数见 JSON。PostgreSQL 必须启用的定向测试使用任务独立数据库；真实 HTTP/账户/订单/重启测试无跳过。私有 runtime 单元测试强制使用冻结 `0.3.1+mf1`；早期公共 runtime 环境拒绝的回执保留，没有把跳过当通过。状态恢复测试在 102 次提交中每次推进历史数据，覆盖完整 checkpoint 与 delta；原有失败回滚和取消后提交回归通过。

优化前、后各跑同一组三脚本、59 步真实部分成交及退出；完整账户、订单、成交、book 和策略持久化状态逐项相等，摘要 `48c26aa5e50e9a8417e8ce7de464eb4cff0a511f65288bb686e0d3a15024ecfa`。该固定正确性用例不是千 bot 异步轨迹等价证明。PostgreSQL 验证为恢复正确性，容量负载使用内存存储。

本轮只消除日志任务移交时的冗余状态克隆及空动作 delta 的提交副本。完整 scheduler 生成、完整 transcript 响应、宿主轮询和 worker 亲和队列仍存在；没有接入新 runtime 版本，也没有完成通用计算 checkpoint、512/2048 根历史接续、长时内存或任意脚本千级容量资格。改动保留在工作区，没有提交或推送。

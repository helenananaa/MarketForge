# Pine 收线排队与完整日志编码复测（2026-10-12）

本轮降低了订单延迟、worker 往返和落后实例，仍未通过千 Pine 容量验收。最终两轮干净候选下单 P95 为 108.1/56.6ms，落后实例为 68/116；对应基线为 380.1/388.0ms、229/232。平均落后实例减少约 60%，平均市场推进 0.986 → 0.978 步/秒，没有提升，严格 1 步/秒和最终零积压均未达标。完整结果、源码摘要和失败回执索引见[机器记录](2026-10-12-pine-dispatch-journal.json)。

## 归因与实现

以已验收的共享 checkpoint 候选为功能基线。新增诊断把宿主待派发队列、worker 获取/往返、Python 输入解码/决策/输出编码、完整日志验证/编码及 worker 返回到提交返回拆开。完整 profile 中 Python 输入解码均值 4.80ms、Pine evaluate 3.58ms、broker 状态隔离复制 2.57ms；输出编码约 0.59ms。后面三项包含在决策阶段内，不能相加。完整日志验证和编码约 106/131ms，worker 返回到提交返回 P95 233ms。原先每次市场 tick 丢弃尚未派发队列；正式干净基线每 30 秒丢弃 7359/8103 个排队项，平均已等待约 1 秒。

修复及优化如下：

- 待派发队列跨 tick 保留、按实例去重；epoch 改变时清空。实际派发读取最新提交状态，既有单实例 in-flight、失败隔离和状态 admission 检查保留。
- 恢复 JSON 的数字范围校验与 payload 编码合并，复用已校验字节。内存日志只补转义元数据头并复制 payload，PostgreSQL 直接使用该 payload。结构校验、快照/投影/幂等、完整 checkpoint 频率、持久化确认后安装和取消后 durable 完成顺序保留；旧 wire 格式及 Unicode/引号/反斜线 room id 对照测试通过。
- Pine worker 使用只读输入缓存，broker 继续复制可变状态；通用 decoder 仍返回独立副本。已经匹配的增量缓存仅独立复制追加尾部，前缀/设置校验、重建回退和资格源码限制保留。
- Pine manifest 启用已有事件前置过滤，仍覆盖完整历史修正、完整性、自己的账户/订单/手续费/条件单/风险、关联市场和额外周期；冷启动、状态不匹配和到期唤醒走完整路径。
- 单独启用过滤后，完整观察由约 2.4 万次降至约 2 千次，但过滤自身累计仍约 24 秒：每次补派任务都会重新创建冻结批次，重复扫描历史。最终候选按**同一份已提交行情 Arc 快照**复用批次。只更新调度状态可复用，任何行情/账户写入发布新身份并失效；提交前读取不能使用旧发布快照。缓存限定在该房间的 worker 生命周期，未改为跨版本的“最后 bar 相同”判断。

四个 Python worker、16 个外部任务许可、原始风险/订单规则、历史 horizon 与容量门槛均未调整。基线和候选使用同一诊断机制；Rust trace 只存在于 bench feature，Python trace 显式启用，记录身份和计时，不记录账户 payload。

派发项龄没有下降：旧路径在 tick 时丢弃队列会截短统计，新路径保留旧项。不能以不同生命周期的项龄直接比较公平性或声称“所有排队已下降”。最终未再发生 tick 重置丢弃；worker 和 journal 等待下降，但队列仍保留大量尚未需要决策的候选轮询。

Python trace 按固定仿真时间 1941000..1971000ms 切片，与精确墙钟测量窗口不同。两轮均值：输入解码约 5.63 → 0.32ms、evaluate 4.20 → 0.99ms、输出编码 0.73 → 0.56ms，broker 可变状态复制约 3.10 → 2.51ms。worker 响应到 commit 返回 trace 的 P95 约 382 → 163ms；commit 返回仅证明调用成功返回，不能证明每个可能过期的 candidate 都获准安装。

最终市场时间 1971000ms，10 秒周期最新 bar 在 1970000ms 收盘。落后实例全部属于该周期，落后一根；15/30 秒组全部跟上。终点 trace 对齐结果：

| 最新收线后的已记录阶段 | E2（68） | E3（116） |
|---|---:|---:|
| 未记录派发 | 52 | 101 |
| 已派发，未记录获得 worker | 2 | 5 |
| 获得 worker，未记录响应 | 2 | 3 |
| 已响应，未记录提交返回 | 12 | 7 |

这是已刷新 trace 与终点状态的对照，缺少记录不能绝对证明从未运行，提交返回也不能代替 durable admission。结果支持剩余积压主要集中在最新收线后的宿主派发窗口，同时存在响应后的提交等待；输出编码不足以解释全部积压。完整 checkpoint 仍约 148ms，四 worker 及按实例亲和分片、宿主逐 tick 候选扫描仍形成串行/排队约束。下一步应进一步拆派发许可与分片占用，并减少无变化实例进入队列；需要保持事件完整性和订单 admission，不能直接提高 worker 数或降低容量门槛后宣称解决。

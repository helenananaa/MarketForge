# Pine 事件过滤与真实历史预热验收（2026-10-11）

本轮完成宿主的提前事件过滤、同批次账户历史索引和插件状态移交。减少了重复观察构造，并消除进程插件闲置缓存中的一份完整 JSON 状态副本。完整计算 checkpoint、长期历史接续与允许延迟的错峰仍未完成；本报告不构成千级任意 Pine 策略容量承诺。

事件过滤实测未显示端到端收益，因此最终默认关闭。需显式设置 `MARKETFORGE_EXPERIMENTAL_EVENT_PREFILTER=1`，或 manifest 的 `host_event_prefilter: true` 才启用；压测器对应 `--event-prefilter`。默认仍启用账户历史共享索引和插件状态移交。`owned-state-*` 是此前自动开启过滤的实验构建（SHA-256 `7d33f2d6b904a1e21744b7e6c564b70ef1780134d4c5da980d5ae9e26795202a`）；`default-policy` 使用最终默认关闭的构建。不要将两者混作同一默认配置。

## 已落地

- 仅对声明为收盘 bar/账户/定时触发、且不依赖盘口的插件启用提前检查。盘口与每 tick 插件保持原来的调度路径。
- 冻结行情批次共享供应历史前缀的内容摘要，以及真实执行回执到各账户的索引；完整性、历史改写、额外周期、关联市场、成交手续费、订单、清算和风险反馈均纳入检查。未变化时在完整观察复制前返回。
- 到期的 `_next_wake_ms` 不会被跳过；缓存必须与已提交状态、配置、factory、种子、未完成动作和 epoch 匹配。拒单、未提交结果或恢复使不匹配的缓存重建。
- 插件通过 `take_snapshot` 将决策状态移交给调度器，缓存自身释放 JSON 数据。下一次真正执行时由 `prepare_reused_call` 恢复已提交状态。原生 bot 使用默认快照语义。
- 检查仍在任务名额取得与状态匹配之后发生，没有消除轮询、队列、状态比较、调度器保存和全量持久化成本。

当前私有 runtime 仍为 `0.3.1+mf1`；增量仅覆盖已有的六个精确源码哈希。默认 512 / 最大 2048 根非空收盘 bar 的明确停止边界保留。没有把未处理 bar 丢掉，也没有把无下单当作不需要推进 Pine 状态。

## 有真实历史的阶梯负载

每档实际 100/500/1000 个 Pine，另加 38 个固定原生流动性 bot。使用 MA、RSI、breakout 三份已接入脚本，参数按种子分散；1000 档有 692 组不同输入，周期为 10/15/30 秒。没有添加执行延迟来打散共同收线边界。

既有门槛为至少目标推进速度的 95%、下单/撤单探测 P95 不超过 250ms、全部初始化和回看窗口覆盖、无错误与无最终 bar 积压。报告也保留严格达到每秒 1 步的单独标记；没有放宽这些门槛。无编译/并行服务干扰只说明两项控制通过，不代表所有机器后台活动都已隔离，更不代表容量通过。

先通过真实 gateway 交易生成最长周期 64 根非空历史；10/15/30 秒周期分别约有 192/128/64 根。随后启动 Pine，20 秒暖机、30 秒测量，以每秒推进 1000ms 仿真时间为目标。各输入回看窗口均已覆盖。预热期间没有 Pine 交易；测量期间持续提交真实成交输入，保存实际订单、账户和成交回执。

CPU 与内存只统计暖机之后的窗口。进程树内存是各进程 working set 之和，共享页重复计数，不能据此宣称存在内存泄漏。跳过比例是暖机结束到暂停后静止采样间的阶段计数差值。它表示少构造完整观察，不表示完成了同样比例的订单或 Pine 运算加速。

无干扰的实验路径 100 档达到既有 95% 近实速门槛且无 bar 积压，但没有严格达到每秒 1 步；500 档约 0.946 步/秒、探测 P95 未通过；1000 档重复仍失败（约 0.608 步/秒、495 个落后实例）。最终默认路径的两轮均记录到编译活动，不计作无干扰容量证据。不能宣称已达到千级容量，也不能据此宣称已测得默认路径的端到端提升。

积压按最终已提交状态与实际非空收盘 bar 比较，包含结束时的边界影响，不能单独代替稳态决策延迟。`_host_observation` 的年龄也不能当作必须每 tick 更新的决策延迟。验收同时保留市场推进、HTTP 下单探测 P95、初始化、回看窗口、输入、错误和积压。

## 对照与负结果

已有无编译/并行服务干扰的 1000 档对照：基线为 0.671 步/秒、测量进程树 4045 MiB；移交修复前候选为 0.644 步/秒、4957 MiB，提前跳过约 82.7%。两者均未达到配置的 95% 推进目标，也均有未处理 bar。一次异步对照的行情与成交轨迹不同，不能把数值差直接宣称为显著回归或收益。

最初候选缺少 ProcessBot 的宿主实例复用，导致提前跳过为零；该候选已拒绝，原始回执保留。后续阶梯出现编译干扰的轮次也保留，不计作无干扰性能证据。最终候选进一步释放插件闲置状态副本，具体效果以上表为准。

最终第一轮 1000 档仍有两个实例未完成初始化，全部脚本已覆盖回看窗口的条件未通过；最终积压最大值包含这两个空状态。旧汇总器因此对 null 状态调用 `.get`，记录 `final_receipt` 异常，但 scheduler 已保存。已修复汇总器，空状态仍计作未初始化，随后按同样 20 秒暖机/30 秒测量配方复跑，不删除原始失败回执或放宽门槛。

固定工作对照只测同一冻结波次里历史准备/摘要的工作：384 根真实内容 bar，1000 个账户 ID，五轮交替各 5000 次检查，完整准备约 0.122ms/次，已缓存摘要约 0.001ms/次。此用例中的账户 ID 没有已出资账户记录；不包含动态批次、真实私有账户负担、解释器、排队、提交和持久化，不能推算任意脚本容量或端到端加速。

## 尚未解决的主线

无干扰的失败用例没有证明机器 CPU 已跑满；约两个逻辑核的平均占用也不能证明数据库饱和。这些容量测试使用内存存储。阶段计时显示房间持有时间和 worker 等待仍长，但它们是嵌套累计墙钟时间，不能相加后归因给某一个函数。

代码仍保存完整 bars、accounts、providers 和 evaluations transcript；状态复制、JSON 对象展开、调度器快照与定期完整 scheduler checkpoint 会随历史和实例数增长。释放插件缓存的一份副本没有消除这些结构成本。参数分散和长周期能减少实际信号或 bar 更新频率，但不能自动消除这些状态路径。

后续优先紧凑持久化与状态保存路径，再补完整计算 checkpoint 和历史接续；checkpoint 必须包含变量、series、TA、对象、请求上下文与账户反馈，绘图快照不能替代。允许延迟的错峰需要每策略的最大延迟预算，账户成交、风控和恢复必须及时处理，并按顺序推进所有影响状态的 bar。增加社区源码只能在逐段执行与真实账户反馈一致后扩展增量白名单。

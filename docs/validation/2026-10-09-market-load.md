# MarketForge Release 负载与订单到达反馈验证

日期：2026-10-09。目标是区分 bot 数量、服务吞吐和页面渲染的瓶颈，同时验证
随机到达和有限资金下的深度补充。本记录延续现货＋永续结构。

## 可比负载实验

`scripts/benchmark_market_load.py` 每档启动独立 Release 服务，以旧 38 bot 配方
为冻结模板，增加独立账户的噪声交易员到 100／200／500。套利两条腿保留原有
共用账户；其他新增交易员各有账户。六个做市商的初始资金和报价深度按人数比例
明确放大，没有运行时注资。初始账户、参数、种子、每档进程日志全部留存。

服务以 25ms 配置推进，每步市场时间为 1 秒。预热 3 秒、测量 20 秒；并行发出
读时钟、读市场视图、真实限价下单与撤单探针。下单使用独立有限资金账户，
价格为 1 的买单，撤销回执中真实 `OrderRested` ID。客户端超时 3 秒，内存
防护线 1024MiB。所有 bot 的账户腿实际得到观察；各档没有 bot 决策错误。
报告 `active_bots` 表示至少得到过观察，不能当作同时下单人数；有限资金和
风控会让一部分 bot 停止开仓，故没有证明 500 个 bot 每秒持续下单的容量。

两版使用完全相同的冻结配方、人数、种子与探针。没有与本任务的编译或其他
负载实验重叠；共享机器上的其他既有服务未停止。单次短窗口不代表长期容量。
存储为内存耐久日志，没有把 PostgreSQL 延迟混入这组比较。

500 bot 原版另有 9 次时钟／视图／下单超时；表中原下单 P95 仅来自 9 个成功
请求，不包括超时，不能当作完整尾延迟。修复后四档均没有探针错误，下单样本数

250ms，但 500 bot 最大撤单仍有 586ms。只有 38 bot 达到本实验的时钟阈值
38 步／秒（配置目标 40 步／秒）；较高人数尚未达标。

峰值内存不能直接跨版当作优化率：修复后相同墙钟时间推进了更多市场时间，

原内存反映了处理停滞。未证明长期运行的内存有界。

## 定位与修复

增加互不重叠的调度阶段累计微秒计数：等待、克隆、应用动作、保存快照、日志提交。
它们是实际阶段累计耗时，不能直接当作 HTTP P95。500 bot 原版调度动作应用
累计 23.87 秒，日志提交 0.49 秒；主要瓶颈处在动作应用。

永续跨保证金刷新逐账户调用 `sync_cross_margin_account`，每次都复制整本账户、
订单保证金和上下文。改为只保存本次修改账户及上下文，失败时精确恢复原来的
存在性和值；保证金计算、全部账户刷新和风险检查保持原语义。已有与新增账户
溢出路径均验证完整序列化状态不变，其他账户不受影响。

500 bot 修复版动作应用累计 11.44 秒，却处理了约十倍的时钟步数。仍有全账户
保证金刷新、候选房间复制与日志投影开销；这轮解决了最大的重复复制，尚未
完成大规模事件调度或长期日志／内存优化。

## 到达与有限流动性

新增可选噪声订单指数等待和首次随机延后，随机状态可恢复；同价自有报价
低于目标深度 80% 时只追加缺口，保留旧订单队列位置。数量随波动收缩的尺度
可配置，避免在价格 tick 单位放大后过早收缩到 1。

默认原生参数和原 33 bot 配方保持旧行为。38 bot 微观结构配方启用这些机制，
联合校准需显式加 `--feedback`。没有改变资金、库存、保证金或成交真实性。
时钟仍量化到 1 秒，不能声称复现真实毫秒级到达。

重新完成十候选拟合（120 秒）、前三名种子 19 复核及三个独立种子 240 秒评估。
固定配方后才读取同一 2025-01-02 历史留出段，源码没有用留出数据选择参数。
新选候选 2，共 109 bot，宽度比例 0.08、初始深度比例 8、活动率 0.8、市价比例
0.9。旧研究候选 7 共 96 bot；这是两次独立拟合后的结果，不能拆成单项机制
因果贡献。

现货密度和两边波动尺度更接近；永续聚合密度、方向延续性退步。新永续聚合数量

## 浏览器与刷新

先使用相同旧网页包和冻结周期配方对比服务两版，真实房间读取、事件和 bot
状态持续刷新。Chrome 自动化运行在 headless 模式；页面的 visibility 为 visible，
1280×720，独立采样 10 秒。这组帧数据只描述自动化浏览器，不能当作桌面 GPU
帧率或所有机器的流畅性保证。

| bot | 修复版房间请求 P95 ms | 最大帧间隔 ms | 大于 50ms 长任务 |
|---:|---:|---:|---:|
| 38 | 17.7 | 8.3 | 0 |
| 100 | 29.2 | 8.4 | 0 |
| 200 | 49.3 | 8.4 | 0 |
| 500 | 741.1 | 24.9 | 0 |

原服务 500 bot 同包页面房间请求 P95 为 3121.3ms，也没有超过 50ms 长任务。
因此本窗口主要发现行情请求延迟，渲染主线程没有出现同样的停滞。口径合并
view／agents／events 请求，不能替代服务下单延迟。当前页面图表本身较简单，
没有资格替代 CandleScope 多图／真实 K 线压力测试。

完成式轮询替换固定 900ms 间隔：上一轮三类请求全部结束，再等待 900ms 发起
下一轮，切换房间或品种时停止旧循环。最终反馈配方和新网页的四档短采样也未
发现长任务；其工作负载改变，不能将新延迟全部归因于单一性能修复。
500 bot 增加 1200ms 人为读请求延迟，14 秒窗口内最大在途刷新请求 3，完成
24 个读取、无失败，验证没有跨轮积压。控制行在 1280px 截图中正常换行，
修复了新增可选复选框挤压成竖排和覆盖内容的问题。

回执：`output/playwright/market-load-optimized/`、`market-load-baseline/`；
最终新配方 38／100／200 档见 `market-load-feedback/bots-*`，500 档见
`market-load-feedback-final/`。后一目录还有慢刷新回执。最初慢请求探针清理路由
时与在途处理冲突，失败日志保留；改用等待在途处理完成的
[Playwright 清理方式](https://playwright.dev/docs/api/class-page#page-unroute-all) 后重测通过。
没有把那次探针失败当作产品失败或成功。

随后以真正可见的 Chrome 窗口 (`--headed`，进程启动参数确认无 `--headless`)
补测最终配方 38／500 bot。10 秒窗口最大帧间隔分别 8.5／25.1ms，没有大于
50ms 的帧间隔或长任务，房间请求 P95 分别 10.3／765.6ms，HTTP 错误和读取
失败均为 0。回执 `output/playwright/market-load-headed/`。因此本地可见页面
短时没有发现渲染卡顿，但 500 bot 的行情响应仍明显较慢，不能推广为长期或
其他机器的保证。帧采样只覆盖当前市场页，未覆盖其他面板和多图工作台。

## 账户、恢复和检查

新 38 bot 配方使用修复版 Release 服务和本任务独立 PostgreSQL 数据目录，
压缩消息／任务时间线后推进到 31 步，暂停服务，分别重启数据库与服务。
恢复后的调度器、时钟、38 个账户腿的观察（盘口、订单、资金费、状态和消息）
完整 JSON 与重启前精确相同。恢复后继续推进到 60 步，无 bot 错误；实际 POV
累计成交从买 6／卖 0 增至买 14／卖 11，峰值工作集约 28.3MiB。该值属于
短压缩恢复场景，不能代替 500 bot 或长时间内存测试。没有延长订单 TTL。
本任务数据库和服务均已自行停止；现有用户服务未接入或停止。

回执 `.local/market-load/postgres-recovery/`。这轮没有重做 500 bot PostgreSQL
负载，所以内存日志的性能数不能外推到数据库吞吐。

Rust workspace 463 个测试、额外研究／耐久运行器一致性测试 1 个通过。
一致性测试用 33 bot 和当前 38 bot 各跑 72 步，逐笔执行历史、订单 ID、资金费、
账户和 bot 状态相同。Python 22 个市场／配方／HTTP 检查通过；追加改动后
联合校准和负载的 11 个相关测试重新通过。Rust 格式、全 workspace／all-targets
Clippy 严格检查、TypeScript／网页生产构建、Git whitespace 检查通过。

最初完整 Rust 测试遇到系统 Windows `python3` 别名无法执行（9009）；改用已有
仓库 `.venv/Scripts` 后全部通过。Python HTTP 首次指向旧 debug 二进制，随后
显式指定本轮 Release 二进制重测通过。此前基线探索曾与编译或其他负载重叠，
均保留在 `.local/market-load/baseline*`，正式比较只使用 `*-final` 两组。

剩余重点是：细化市场时钟与到达事件、永续订单流相关性／聚合残差、全账户风险
刷新和候选状态／日志投影、长期资金与库存耗尽、长期内存及数据库压力。
策略数量与 bot 数量已经不能单独解释这些差距。

页面；需先在 15281 端口提供构建后的网页。它保存完整截图、页面快照、10 秒

# 大量策略接入：运行时改造与有限负载验收

已按事件调度、常驻进程池、Pine 增量执行、公开计算共享、混合负载验收的顺序实现。
当前成果是受限的接入基础和可复现证据。单房间 1000/3000 bot 仍未达到 40 步/秒，
不能据此批量启用整个已保存策略库。

## 实现范围

1. `decision_trigger` 默认保持每 tick；事件模式按收盘历史、盘口/成交、自己的账户与
   回执或指定仿真时间周期唤醒。游标与策略状态一起提交，恢复后可跳过相同输入。
   `_next_wake_ms` 支持安静行情中的对冲补偿。历史改写和截断仍会唤醒并交给消费者拒绝。
   公开累计成交量只属于盘口事件，避免收盘/账户策略被每次公开成交唤醒。
   Pine 默认使用收盘/私有反馈与补偿 deadline；撤改单、条件单和保护单依赖宿主私有反馈，
   持续限价单的撮合仍由网关驱动，不需要每次盘口变化都重算无动作的策略状态。
2. 可选 `bot.worker.v1` 共用进程池。每个插件 1–32 个 worker，当前两个示例各 4 个；
   自动调度全服务最多 16 个外部决策、32 个常驻 worker，每实例最多一个在途请求。
   跨插件满额时淘汰最久未用的空闲 worker，忙碌进程保留；重建只使用已提交状态。
   等待和执行共用 deadline，
   不堆积跨 tick 补跑队列。协议身份、尺寸、stderr 累计上限和失败回收均有限制；失败不
   自动重试。旧的一次性进程协议仍可使用，池协议可由 Python、C#、Rust 等语言实现。
3. Pine 编译缓存 64 项，增量 session 每 worker 最多 64 项。缓存必须匹配已提交的完整
   bar/账户/pass 前缀与设置；重启、淘汰和未提交计算都从 durable transcript 重建。
   只有 `incremental-qualified.json` 中的 6 个精确源码允许增量，其他源码和 legacy
   模式完整重放。私有 `0.3.1+mf1` adapter 从固定 v0.3.1 源码构建，未修改上游工作区，
   未替换全局 wheel，未发布为上游版本。
4. 同一冻结观察 wave 共用历史索引和各周期公开 K 线聚合；账户输出分别过滤。
   新增原创标准库 `python.sma@1.0.0`，有 128 项公开均线结果缓存，余额、库存、
   私有状态独立，订单遵守 tick/lot 精度。没有把社区框架代码宣称为等价原生移植。
   当前没有足够的热点归因证据选择社区策略进行 Rust 重写。
5. 保存阶梯、固定输入、固定完整交易与异步对照的独立记录，并统计服务端及其子进程。

接入协议见 [BOT_PLUGINS](../BOT_PLUGINS.md)，构建与 Pine 边界见 [PINE_BOTS](../PINE_BOTS.md)。

## 正确性和构建

- 最终 Rust 全工作区：590 passed，13 项受控诊断/基准 ignored，PostgreSQL 必须可用。
- Python：35 项 Pine/broker/HTTP 测试、6 项增量/缓存/共享信号测试、1 项固定完整交易
  对照，共 42 passed；Pine、增量和 PostgreSQL 所需项没有静默跳过。
- Clippy `--workspace --all-targets -- -D warnings`、正常 Release 构建、诊断 feature
  `memory-diagnostics,bench-execution-timing,risk-benchmark` 的 test 编译检查通过。
- 12 个实例同时请求时，2-worker 池实际只创建 2 个执行进程；超时、错误身份、超大输出
  和 stderr 越界均保留宿主原状态。跨实例轮流运行及恢复只使用请求携带的状态。
- 35 个独立插件池依次调用时，全局保留量最多 32；最早池被淘汰后从已提交状态
  恢复计数，所有池释放后总量归零。
- 6 个源码 × 3 个 seed × 32 个历史前缀，576 次增量与完整重放返回值完全一致；
  包含缓存丢失、未提交计算、历史改写拒绝、64-session 淘汰后重建及非法 pass 拒绝。
- 3 个现货脚本的 59 个固定真实撮合步骤，两种 worker 模式的策略状态、账户、挂单、
  成交和盘口逐步一致；确实出现两单位请求只成交一单位，随后实际平仓。

PostgreSQL 使用本任务的独立 cluster 和独立 Rust/HTTP 测试数据库；`fsync`、
`synchronous_commit`、`full_page_writes` 均为 on，验收后已停止自己的 cluster。
这证明恢复正确性，不表示下面的内存 journal 压测也验证了 PostgreSQL 容量。

## 固定输入计算收益

同一私有 runtime、提前编译、6 个源码各推进 128 根 bar，完整重放 → 增量 → 增量 →
完整重放四轮耗时分别为 6.656、5.156、5.164、6.232 秒。每轮 768 次决策，完整响应与
状态摘要一致，平均耗时减少 **19.93%**。增量每轮 6 次重建、762 次追加，只评估 768 根
新 bar。该实验使用冻结的合成账户反馈；它是固定计算路径收益，不是实际交易吞吐提升。

## 最终混合阶梯

独立正常 Release；每档 5 秒预热、30 秒测量；seed=7，25ms wall tick 推进 1000ms
仿真时间，目标 40 步/秒；80% 原生、10% 已验证的 Pine ma/rsi/breakout、10% 原创
Python SMA。资金有限，主策略读取非空收盘 K 线，周期 10/15/30 秒。
下单/撤单探针位于独立空品种 `LOAD-PROBE-SPOT`，避免改变策略交易盘口。

| 总实例 | 时钟步/秒 | Pine 最大 bar 积压 | Python 最大 bar 积压 |
|---:|---:|---:|---:|
| 100 | 39.98 | 0 | 0 |
| 500 | 39.99 | 0 | 0 |
| 1000 | 32.71 | 3 | 2 |
| 3000 | 21.30 | 9 | 9 |

全部实例初始化，没有 HTTP 或 bot 错误。bar 积压是暂停后的最终 durable snapshot 与
同一时点实际非空收盘 bar 数量之差；暂停会丢弃未提交计算，这不是稳态延迟 SLO。
没有新成交产生新 bar 时，最后观察时间很旧也不表示遗漏了策略输入。1000 档有
62 个 Pine、66 个 Python 实例落后收盘输入；3000 档两类外部策略全部存在 bar 积压。

| 总实例 | 服务端峰值 MiB | 进程树采样峰值 MiB | 下单 p95 ms | 撤单 p95 ms |
|---:|---:|---:|---:|---:|
| 100 | 134.3 | 338.3 | 19.3 | 17.1 |
| 500 | 463.8 | 689.8 | 27.8 | 30.0 |
| 1000 | 1332.7 | 1697.0 | 55.1 | 46.1 |
| 3000 | 1780.0 | 2068.4 | 120.2 | 64.7 |

各档进程树最多采到 18 个物理进程（服务端、8 个逻辑 worker 与 Python 启动辅助进程）。
这组两个插件的负载没有用满 32-worker 全局预算；跨插件预算由独立 35-pool 测试验证。

原驱动的 95% 时钟容差继续保留；报告另记字面上的 `>=40`，没有放宽性能目标。
所有资源数字的定义、原始 samples、bot 状态和源码/二进制摘要见同名 JSON 和本地
`.local/strategy-runtime-20261011/`。进程树每 250ms 采样，包含初始化、预热和测量；共享页面按各进程
working set 重复计数，短命子进程可能被漏采。Windows Python 启动器可多出辅助进程，
所以物理进程数不等于逻辑 worker 数。服务器本身的 CPU/memory 与进程树数字分开保存。

## 异步 500 实例对照

同一最终二进制、相同初始 recipe/seed 和独立探针，按 A1 → B1 → B2 → A2 顺序运行。
A 为每 tick 一次性进程、公开 0.3.1 完整重放；B 为事件调度、常驻 worker 和私有增量
adapter。A 也使用新宿主的全局 16-task 配额和公开观察共享，因此不是旧无界宿主的基线。
每轮仍为 5 秒预热、30 秒测量。异步完成次序、成交及后续市场路径可能不同。

| 轮次 | 步/秒 | 进程树峰值 MiB | Pine / Python 最大 bar 积压 |
|---|---:|---:|---:|
| A1 一次性 | 31.78 | 1074.7 | 31 / 32 |
| B1 常驻 | 39.34 | 963.1 | 0 / 0 |
| B2 常驻 | 37.00 | 1263.1 | 1 / 5 |
| A2 一次性 | 38.09 | 619.5 | 0 / 0 |

这轮 A 平均 34.93、B 平均 38.17 步/秒，观察到 +9.26%。每模式只有两个样本，
B2 未达到时钟目标并存在积压；不能把它当作稳定整体加速或 500 实例生产容量证明。
原始响应/状态等价由独立固定计算及 59 个固定真实撮合步骤验证，异步实验并不声称
产生完全相同的订单轨迹。

保留前两组对照：早期实现 A/B 平均 37.36/38.43（+2.88%）；公开事件字段修正、
Pine 仍含盘口触发的阶段为 37.35/36.68（-1.79%）。不同阶段的触发和市场路径不同，
不能直接据此给某次修改分配因果收益。全部 12 轮、阶段阶梯及失败记录均纳入
[机器可读报告](2026-10-11-strategy-runtime.json)，没有删除负结果或只选择最快轮次。

## 失败记录和实际边界

- 首次 pilot 使用了 Pine 不接受的 20 秒周期；修正为显式支持周期，保存失败记录。
- 首次进程池复用发现持有 slots mutex 的死锁，已在取出 worker 时释放锁，补并发验证。
- 全量测试一次缺少 virtualenv PATH，且 Rust 与 HTTP 共用了含 Pine 存档的测试库；
  重新隔离数据库和解释器后通过。原失败日志保留，未降低测试要求。
- 共享工作区的事件查询曾将可选时间戳与整数直接比较；最小修复恢复构建后重新验证。
- 原价格 1 的买单探针可能真实成交，导致 `OrderRested` 查找失败；改为远价卖单又在
  空盘口影响 bot 中间价，原生状态确实记录约 5 亿的中间价。两组探针影响记录全部保留，
  最终使用独立品种；不把受影响的阶段当作隔离探针容量结果。
- 原事件摘要包含公开累计成交量，导致 SMA 非必要唤醒；按声明选字段后重新跑 Rust、
  HTTP、恢复、固定完整交易和阶梯负载。此前有效记录也保留，不拿前后不同市场轨迹
  直接当作这一处修改的因果性能收益。

尚未完成长期 Pine checkpoint/归档接续；默认 512、最大 2048 根非空 bar 及消息上限
仍然存在。多周期 provider transcript 也有额外体积，缓存不会解除 durable 历史上限。
worker 池限定数量和请求尺寸，尚没有给任意第三方代码提供 OS 层内存/CPU 硬限额。
未重新验收整个上游语言矩阵、全部社区脚本、纯外部策略人口、持续高交易量或长期
PostgreSQL 混合负载；saved library 的 `not_qualified` 状态保持原样。

1000/3000 档不能按 40 步/秒容量部署。后续需要依据真实热点和信号频率做任务频率、
分进程/房间分片与持久增量 checkpoint 验收；多房间共用进程仍受全服务 16 个外部任务
限制，不能假设线性扩容。当前证据不足以承诺任意语言、任意社区策略的数量上限。


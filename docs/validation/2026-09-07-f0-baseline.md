## 事务边界（F0.2）

权威写入路径约定：`authorize → clone candidate RoomManager → apply → journal 事务（可选 fencing）→ 安装 candidate → 发布`。`run_durable_state_transaction` 把该区间放到 detached Tokio 任务，HTTP 取消不能中止提交后安装。内存 journal 同进程等价，不承诺跨进程。

### 控制写入（pause / resume / close / clock/step / clock/advance）

```text
pause:
  读内存 map (user, room, key) → 指纹!="pause" 则 409
  → durable tx: clone rooms → pause → StatusChanged mutation 提交
  → 安装 rooms → 写入内存 control_idempotency

clock/step:
  读内存 map；指纹!="clock/step" 则 409
  → 要求 Paused + 已有 scheduler
  → commit_scheduler_step（见下）成功后另写内存 map
  （幂等结果不在同一 journal 事务内）

resume / close / clock/advance:
  不读不写 control_idempotency
```

`HttpTradingClient::{pause,resume,close,advance}_room` 默认不发送 `Idempotency-Key`。CLI 仅在全局 `--idempotency-key` 时给所有 POST 带头。Python SDK 只在下单接口暴露该参数。

### 订单写入

```text
authorize Account(account_id)
→ durable tx:
   非 admin：内存 (room, user, clock.step) 计数 +1（先于受理，失败事务不回滚该 map）
   查 journal 订单幂等 (user, room, key)；指纹不同 → 409
   训练 allows_trainee_action / remaining_buy_capacity
   clone rooms → OrderGateway → book_before 快照
   apply_training_execution；若训练结束则 settle_training_residuals(candidate)
   journal_new_executions（含订单幂等列）
   persist_training_progress（若有 run）
   安装 rooms / next_order_id / 发布执行
```

订单幂等走 `marketforge_order_request_idempotency`（迁移 0010），与控制 key 空间分离。

### 调度步 `commit_scheduler_step`

```text
durable tx + lease claim
→ clone rooms → run_scheduler_step
→ 对 live training_runs 克隆应用成交/on_step/settle(candidate)
→ 先 insert 回 live training_runs
→ SchedulerProgress mutation + executions + 可选 snapshot
→ persist_training_progress（第二次 mutation）
→ 安装 rooms / next_order_id / schedulers
```

市场状态与调度进度在 `append_room_mutation` 成功后才安装 rooms。训练 map 在 mutation 前提前写入 live；journal 失败时存在内存训练状态领先于 DB 的窗口（F2 验证点，不是本步回归）。

### 训练结束

调用 `settle_training_residuals` 的入口：

| 入口 | 作用对象 | journal |
| --- | --- | --- |
| `commit_scheduler_step` | candidate rooms | SchedulerProgress 后 `persist_training_progress` |
| `advance_room_clock` | candidate rooms | ClockAdvanced 后 persist |
| `submit_order_response` | candidate rooms | 订单执行后 persist |
| `abort_training_run` | **live `app.rooms`** | 先 `append_executions` 再 persist |

`close_room` 只写 `StatusChanged`，不调用 settle。冻结不另存布尔：`TrainingRun::allows_trainee_action` 要求 `status==Running && !paused`；账户分配冻结为 `training_assignment_frozen`（房间存在非 Created 的 run）。恢复：`training_runs_from_recovery` 按 mutation_seq 重放全部 `TrainingProgress`。

`persist_training_progress`：写 `RoomMutation::TrainingProgress` 成功后再 `training_runs.insert`。abort 路径在 persist 前已改 live 房间挂单。

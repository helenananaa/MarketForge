# 永续资金费

资金费在多空持仓账户之间收付：正费率由多头支付空头，负费率反向；结算金额基于结算时的标记价与持仓数量。这一方向与线性永续的常见口径一致，参见 [Bybit 官方资金费说明](https://www.bybit.com/en/help-center/article/Funding-fee-calculation)。MarketForge 使用下面的仿真费率模型，不复制某家交易所的完整溢价指数或利率阻尼算法。

## 配置与时序

在已配置 `price_link` 的永续市场中加入：

```json
"funding": {
  "interval_ms": 28800000,
  "base_rate_ppm": 100,
  "max_rate_ppm": 1000,
  "min_coverage_ppm": 900000
}
```

省略 `funding` 表示关闭。`"funding": {}` 使用上面的默认值：8 小时、基础费率 0.01%、上限绝对值 0.1%、最低有效行情覆盖率 90%。基础费率是每个周期的有符号费率；不是年化利率，也不会随周期长度自动缩放。`max_rate_ppm` 允许 0 到 1000000，基础费率的绝对值不得超过上限。周期至少 1000 ms，且必须是 1000 ms 的整数倍，对齐当前一秒仿真步长。`min_coverage_ppm` 允许 1 到 1000000；设为 1000000 可要求完整覆盖。没有现货价格绑定的永续不能启用资金费。

时间从房间仿真时间 0 开始，在 `interval_ms` 的整数倍结算。资金费只随仿真时钟推进，HTTP 查询、下单和墙上时间不会自行计费；实时 worker、调度器与手动推进时钟走同一结算路径。暂停房间仍可由管理员明确推进仿真时钟；关闭房间不能推进。每个仿真步先推进时钟、处理到期划转、采样并结算资金费，再扫描强平和执行交易者决策。持仓在边界后的新订单不会被追溯计入刚结束的周期。

资金费房间的批量时钟推进逐步处理强平，避免已经应当平仓的账户继续跨多个周期付款。未启用资金费的房间保留原来的批量推进行为。

## 费率与金额

每一步使用该步期间保持的永续最优买卖价与现货指数，保留盘口中间价的半 tick 精度：

```text
premium_ppm = trunc(((perp_bid + perp_ask) / 2 - index) / index × 1000000)
sample_ppm  = premium_ppm + base_rate_ppm
rate_ppm    = clamp(trunc(time_weighted_mean(sample_ppm)), -max_rate_ppm, +max_rate_ppm)
payment     = floor(abs(position_qty) × mark_price_tick × abs(rate_ppm) / 1000000)
```

中间运算采用整数与检查过的 i128 算术。先平均，后限幅。永续标记价仍直接跟随现货指数，永续独立盘口提供资金费溢价；不使用标记价减指数价作为溢价，否则绑定市场的溢价会恒为零。

支付账户向下取整；收取账户按持仓数量分配本周期实际支付总额，余数采用最大余数法，余数相同时按账户 ID 升序。资金费总收付严格为零，不进入交易手续费或保险基金。金额单位沿用现有整数 quote 单位，小额周期可能舍入为零；没有跨周期保留小数尾款。

只向结算边界仍持仓的账户计费；整个周期内累计的是行情样本，不是每个账户的持仓时间。非零净持仓的异常市场跳过结算，避免凭空产生收付。既有强平的保险、ADL、社会化损失与坏账处理仍使用原流程。

## 不完整行情与风险

现货指数必须有效，永续必须有有效的两侧盘口，并且采样步末现货来源尚未过期。周期有效行情覆盖率达到配置门槛、且结算边界的行情仍有效，才可结算；否则保留 `skipped_prices` 回执。平均费率只使用实际覆盖的时间，不把缺失数据补为零，不按缺失比例降低费率，也不会等行情恢复后追扣。回执公开实际 `covered_ms`，便于判断覆盖质量。无持仓周期记录 `no_positions`，净持仓不平衡记录 `unbalanced_positions`，正常收付记录 `settled`。

扣款减少现金、权益和可用保证金；`funding_pnl` 记录累计有符号现金流，正值是收到，负值是支付，与交易 `realized_pnl` 和 `fees_paid` 分开。风险仍按完整保证金要求计算；在启用资金费的 quote 全仓组中，实际现金冻结受余额约束，缺口不被当作可用资金。资金费产生的负现金保留为持仓债务，进入既有强平与破产处理，不截断支付金额。受损账户不能增加风险，仍能通过支持的 reduce-only 市价或 IOC 订单减仓。

## 回执、恢复与网页

- view、ticker 和 observe 的 `perp_price.funding` 返回周期、预估费率、覆盖门槛、下一结算时间、已覆盖时间和上次结算回执。
- 系统执行记录的 `funding_settlement` 是公共汇总；每个账户的 `PerpFundingSettled` 是清算明细，账户账本标记 `account_side: "funding"`。
- 公共事件流只发汇总；私人资金费事件按账户权限过滤，管理员可查看完整清算明细。
- 周期累计值、下次结算游标、累计账户收付与抵押缺口随快照保存。时钟 mutation 与资金费系统执行一起入日志；恢复重新计算并核对回执，不能通过交易者命令自行触发结算。
- 网页显示预估费率、距结算的仿真秒数、上次结算状态与覆盖率，以及当前账户累计收付。

新绑定配方和 AI arena 配方启用 **60 秒仿真周期、100 ppm 基础费率、10000 ppm 上限、80% 最低行情覆盖率**，容纳做市商撤单重报的短暂空档，方便演示；与默认 8 小时配置不同。新配方由 `scripts/linked_market.py` 导出，旧房间没有自动迁移。

本轮没有新增自动套利交易者、跨交易所指数、基差平滑或交易所专属资金费规则。

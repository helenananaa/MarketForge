# Agent 订单、警报与可选规则

业务服务仍不运行模型循环；工具通过原有 MCP/HTTP 接口供外部 Agent 使用。

## 订单工具

- `trade(action="amend", instrument, order_id, price_tick?, qty?)`：`qty` 是新的剩余数量。沿用交易所规则，只能减量或改为更不激进的价格；买单加价、卖单降价及增量会产生 `AmendRejected`。增量/追价应先明确撤单，再以新请求提交新订单。改单不修改原订单过期时间。
- `orders(instrument, limit?, order_id?, strategy?)`：自身账户最新订单历史，含状态、剩余数量、市场时间及 `sources` 来源归属。
- `fills(instrument, limit?, order_id?, strategy?)`：自身成交记录，含成交价、数量、订单编号、市场时间和来源归属；不返回对手账户编号。
- `order_cancel_all(instrument, strategy?)`：固定当前自身挂单快照，逐笔撤单。可仅撤某个策略的挂单。每笔保留独立持久请求身份；网络结果未知时重试原请求。中断后核对已提交的子请求，未提交部分返回 `held_order_ids`，重新决策后用新批次处理。

批量撤单是顺序操作，非交易所原子事务。查询默认最新 100 条，最多 500 条；订单/策略筛选在这段自身账户历史内进行，`history_may_have_more=true` 表示可能还有历史，不声称完整归档。手动订单来源为 `untracked`，Agent 直接交易为 `direct`，策略订单为策略名。归属由业务服务接受订单的回执记录，重启后保留。策略只能改/撤自己的订单。

交易回执的 `accepted=true` 表示命令获接纳，应检查 `OrderAmended`、`AmendRejected`、`TradePrinted` 等事件判断实际效果。旧凭证不能提交新动作；已提交而结果未知的订单可使用原参数、原请求身份核对。只预留、尚未提交的请求在旧凭证失效后会被挂起。旧版本产生且缺少提交追踪的未知订单保留不确定状态，需要核对交易所回执。

## 警报

`alert_set` 新字段：

| 字段 | 默认 | 行为 |
| --- | --- | --- |
| `priority` | `urgent` | `urgent` 立即中断；`normal` 排队到下一轮，不改变当前代际或凭证 |
| `sustain_seconds` | 0 | 0–3600 秒，连续匹配的采样持续时间；不匹配或缺失数据重新计时 |
| `hysteresis` | 0 | 重复布防阈值的回差，使用条件指标的单位；仅支持 gt/gte/lt/lte |
| `interrupt_min_interval_seconds` | 0 | 0–3600 秒，本次紧急触发须距该交易员上次中断至少这么久 |

重复规则仍须退出触发条件并经过 `cooldown_seconds`。以 `gte 100`、回差 3 为例，价格须降到 97 以下才重新布防。`all` 任一条件达到退出边界即可重新布防；`any` 所有条件达到退出边界才可。限频期间保持条件成立会在后续检查再次尝试，不会静默取消规则。

普通警报按名称合并最新证据，通过 `context.notifications` 供下一轮决策读取；当前决策/原生活动轮次结束后合并唤醒，开始新决策后确认清空。普通警报不能设置 `pause_strategies=true`。紧急警报继续保留旧目标和计划，阻止未发送的旧动作；Agent 可以继续、调整或放弃计划。

采样周期仍为约 250ms 加读取延迟，跨市场读非原子；这里没有接入逐事件行情流，短于采样间隔的穿越仍可能漏检。持续时间、冷却和间隔使用现实时间，`market_time_ms` 条件使用仿真时间。暂停期间不监测；服务重启清除持续条件候选计时。

## 可选账户规则

运营接口 `GET/POST /traders/{id}/policy`。POST 完整替换下面两个对象；空对象关闭规则。AI 的 `policy_status` 只读。保存规则撤销旧决策并发布业务唤醒。

```json
{
  "account": {
    "V-BTC-SPOT": {
      "max_abs_position": 20,
      "max_leverage_bps": 15000,
      "max_loss": 2000
    }
  },
  "model": {
    "max_admissions": 100,
    "max_tokens": 1000000,
    "max_estimated_cost_microusd": 5000000,
    "microusd_per_million_tokens": 5000000
  }
}
```

这里的数值仅示例，非默认或建议额度。账户规则**按市场**检查，不是跨资产组合杠杆上限：仓位取当前持仓加买挂单/减卖挂单的最坏边界；杠杆取该边界绝对数量 × 观测标价/订单价中的最高值 ÷ 权益，10000 bps 为 1 倍。金额沿用交易所原生资金单位。亏损比较首次启用时该市场观测权益，修改额度、重启都保留基准；关闭该亏损规则会清除基准，再开启重新建立。资金转入转出也会影响该权益差。

启用规则后缺少必要观测会拒绝增加敞口。撤单、减仓和同价减量仍可执行；`reduce_only` 由交易所保证不增仓。杠杆规则启用时拒绝无法确定最高名义金额的无价格上限开仓；关闭该规则可以明确使用 `execution_mode=unbounded`。未知订单重试复用原意图，不因新规则改变参数。规则覆盖本服务的直接/策略交易通道；其他客户端直接下单不由这层规则检查，观测与提交之间也不是交易所原子风险事务。

## 外部框架模型预算

连接器调用 `POST /tools/{id}/model`，需当前 `connection_id` 和绑定 `session_id`：

- `action=admit`、`request_id`：新消息交付前申请一次许可，持久去重。正常唤醒和紧急 steering 都计入 `max_admissions`。许可次数不是模型内部 API 调用次数；已经许可但传输失败的尝试保守计数。
- `action=usage`、`meter_id`、`tokens`：报告累计计数。Codex 使用线程累计 `totalTokens`；OpenCode 使用各 assistant message ID 的用量快照。按快照差额增加全交易员用量，同会话重连不重复计费；计数回退会拒绝并要求核对。

达到 Token/估算费用预算后，撤销旧决策并由连接器停止活动轮次；后续消息等待运营者调整规则。次数预算只限制下一次交付，不在已经许可的最后一轮立即停止。预算不自动平仓、撤销挂单或停止已部署策略。

预算在下一次许可及框架用量报告时检查，已进行的单次推理可能超额。费用为 Token × 运营者提供的统一单价，向上取整到微美元，包含缓存 Token，**不是供应商真实费用或订阅账户账单**。换单价会重新估算当前累计用量。读取恢复会话的既有累计历史也会计入首次观测用量。OpenCode 历史读取仍受连接器 1MiB 响应上限约束；超过时停止连接器并保留业务状态，不能悄悄只计最后一条。

这是可信本机框架连接器的预算控制，不是针对恶意框架进程的计费防篡改系统。绕过连接器直接使用原生框架时，模型预算无法覆盖框架自己的推理调用。账户权限、请求去重及旧决策失效仍由业务接口强制检查。
